# Notion admission contract

## Ownership and authority

`internal/adapter/notion` owns Notion property mapping and bounded HTTP reading. `internal/adapter/intake` coordinates admission. `internal/core/admission.go` checks host-supplied authority synchronously. The production code and original intake fixtures retain the independently reviewed candidate's bytes; this integration changes only the Notion test consumer fixture and public documentation.

The caller supplies an exact task/page/project/workspace/permission contract, an authority reference, an approved brief digest and a source verifier. Notion content, task status, a profile or an agent label cannot create authority. The finite allowlist and exact workspace/permission checks run before coordination access.

Admission reads the task and verifies its source, checks ownership, assignment, dependencies and the brief, then requests a claim and repeats task/source checks. A live lease conflicts even when the agent label matches. Owner, nonce, lease, brief or source drift fails closed. `ADMITTED` retains `execution_started=false`; it is neither a launch grant nor acceptance or DONE. A failed post-claim check does not release or repair another owner's lease.

## Reader contract

The reader accepts explicit UUID pages within the selected data source and reads only direct dependencies. It uses fixed HTTPS GET endpoints, rejects redirects and inherited proxies, bounds responses and timeouts, and redacts credentials and remote error bodies. Configurable property names belong to the adapter rather than core policy.

Required fields use exact JSON names. Missing/null required booleans or arrays, wrong types, exact duplicate keys (including escaped and nested duplicates), and typed-schema case aliases are rejected as `NOTION_SCHEMA_UNSUPPORTED`. This includes archived/truncated fields, select names and the separately decoded lease date start. The JSON decoder's case-insensitive field matching cannot replace the required names.

Valid empty dependency arrays and explicit null lease dates for an unclaimed task remain supported. Known-owner dates, text, renamed property mappings, optional warnings and normal extension objects retain their contracts. Case-distinct names in configurable property maps or untyped extensions are not blanket-rejected. Archived/trashed pages, truncated relations/markdown, unknown blocks, unresolved dependencies and ambiguous briefs are not eligible.

## Tests and consumer boundary

Canonical validation is `make check`. Focused coverage runs:

```sh
go test ./internal/adapter/notion ./internal/adapter/intake -v -count=1 -timeout=30s
```

`TestReaderB1Schema` preserves the 82 negative and 5 positive schema cases, including the original missing/null/duplicate failures, case aliases, empty relation/null date and extension compatibility. Every malformed case reaches the actual Reader and `intake.Admit`; claims, source verifications and fake dispatches remain zero.

The test-local consumer calls `intake.Admit` and records delivery only from an admitted result. It imports no Codex package and substitutes no production reader or policy. `TestReaderAdmissionConsumerFlow` uses real Reader passes over an in-memory HTTP transport. Its positive control updates only the fixture JSON on claim, then observes the re-read owner/nonce/lease, two source verifications and one consumer delivery carrying the verified source/brief identities. Missing authority causes zero access and delivery; a changed post-claim nonce causes zero delivery after the real revalidation path.

These fixtures establish admission-to-fake-consumer behavior only. Historical Codex executor outcome evidence remains separate; it is not an isolated Notion-package acceptance claim. Independent schema evidence remains applicable to unchanged production bytes, while the changed test consumer requires fresh isolated validation and non-author review.

## Unverified service boundaries

Tokens must be provided separately by an authorized caller; credential files and plugin authentication are not inspected. `Reader.Claim` always returns `CLAIM_WRITE_UNAUTHORIZED`. In-memory claim fixtures do not prove atomic live lease acquisition or concurrent-owner safety. Live Notion access/write grants, an actual Git/source verifier, provider jobs, operating-system sandbox/process cleanup and an MCP server are unverified. No intake or launch command is added to the CLI. Source publication does not supply any of those permissions.
