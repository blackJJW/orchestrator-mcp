# Codex adapter corrective contract

## Authority and preserved behavior

The adapter is dormant unless a trusted host supplies a separate read-only launch Grant, approved profile and contract, task store, source verifier and finite timeout. The grant binds task, run, canonical workspace, source, brief, claim nonce and lease. Notion metadata, model responses, process exit0 and source publication cannot create authority. The CLI continues to expose dry-run only.

The native runner retains a host-pinned executable identity, fixed `exec --json --sandbox read-only -c approval_policy="never" -C <workspace> --ephemeral --skip-git-repo-check -` argv and stdin-only brief. It verifies executable and cwd, owns a POSIX process group, cancels that group and bounds stdout/stderr to1MiB each. Results contain stable outcomes and output digests, not raw prompts, model text or diagnostic secrets. There is no fallback, automatic retry or credential-file inspection.

## C1: one attempt and lease-bound execution

The executor atomically reserves both workspace/task/run and workspace/task/claim identities before coordination reads. Reservations are shared across every Executor in the same controller process and remain consumed after success, failure or cancellation. A new grant reference, changed run for the same claim or changed claim for the same run cannot bypass this boundary. Concurrent losers and replays return `EXECUTION_ALREADY_RESERVED` without dispatch. Callers must supply immutable requests and thread-safe host adapters; failed attempts require a separately authorized new run and new claim rather than reusing an old grant.

The request timeout and absolute lease deadline both constrain the context. Task/source/admission checks still precede dispatch. Expired grants cannot start; an expired lease returns `LEASE_EXPIRED` even if a runner ignores cancellation and returns exit0 with successful JSON. A final expiry check follows output classification so parsing cannot promote a completion past its lease. No renewal is inferred.

This reservation is in-process only and retains entries until process exit. It is not a durable journal or proof of ownership across controller processes or restarts. Live operation still needs an independently enforceable host ownership boundary; this corrective slice does not implement the separate journal task.

## C2: unambiguous events and final response

Every JSONL object is checked for duplicate keys, including escaped names and nested objects/arrays, before ordinary decoding. Interpreted event and item keys use exact names; case aliases are rejected. Unknown event types and unsupported agent-message phase fields fail closed.

The reviewed [official0.161.0 event schema](https://github.com/openai/codex/blob/rust-v0.161.0/codex-rs/exec/src/exec_events.rs) contains agent message text without a phase discriminator. Its [JSONL processor](https://github.com/openai/codex/blob/rust-v0.161.0/codex-rs/exec/src/event_processor_with_jsonl_output.rs) selects the last agent message. The controller additionally requires exactly one completed agent message matching its requested JSON response contract: an object containing only string `status` and string `summary`. That candidate must be the last completed agent message before turn completion.

Natural-language progress and JSON progress objects without response-contract keys are allowed before that candidate. Malformed or aliased response candidates, duplicate JSON members, repeated or conflicting candidates, and progress after the candidate cannot become normal completion. Multiple candidates return `UNSUPPORTED_OUTPUT`; malformed candidates return `MALFORMED_OUTPUT`. Explicit final-phase identification unsupported by the pinned schema is not guessed. This controller policy is conservative; it does not claim that the official CLI guarantees one contract-shaped response in every live stream.

Both response values must be JSON strings. `null`, numbers, arrays, objects and booleans are rejected; a permitted empty summary string remains valid. The decoder's successful handling of `null` cannot substitute for a string-type check.

One supported completed response produces only `COMPLETED_UNVERIFIED`; blocked produces `SOFT_DENIED`. Existing provider/tool/quota/timeout/cancel/output-cap/file-change failures remain errors. Neither exit0 nor the final message can set ACCEPTED or DONE.

## Validation and remaining limitations

Canonical validation is `make check`. Task-specific coverage is `go test ./internal/adapter/codex -race -v -count=1 -timeout=45s`, using only in-memory runners and the Go test binary. Tests cover concurrent callers across Executor instances, replay and independent scope, absolute lease deadline and late results, fixture-process cancellation, recursive duplicate keys and aliases, conflicting finals and valid progress. Existing12 fake outcomes and13 unauthorized invocation cases remain required.

Historical correction budget2/2 remains exhausted and its failures are preserved. The user separately authorized one C1/C2 corrective slice with at most2 bounded follow-up corrections; this does not reset that history.

That separate slice has now consumed2/2 follow-up corrections: one test stream newline fix and the final strict string-type fix after independently reproducing `summary:null` as successful completion. Original source/review evidence is preserved. Further defects require a new authority and budget decision; no third automatic correction is allowed.

Actual provider authentication/jobs, live Notion claims, a real Git/source verifier, official output applicability, operating-system sandbox and complete descendant cleanup remain unverified. Executable/cwd verification-to-spawn replacement races, descendants that leave the process group, and inherited configuration/environment effects still require a separate launch safety contract. No journal, daemon, MCP server, CI or live smoke is added. A Draft PR is source review material, not operational qualification.
