# MTT-574 stage A: local fixture journal

Stage A implements local fixture ownership and recovery only. The explicit user grant
partially exempts this stage from MTT-589's unresolved live approval. Depends On remains
unchanged. MTT-589 stays BLOCKED/HUMAN_DECISION with FIXTURE_POLICY_APPROVED /
LIVE_AUTH_PENDING. Stage A acceptance is not full MTT-574 acceptance or DONE.

## Fixed scope and persistence

`journal.OpenFixture` takes an explicit canonical project profile and uses the fixed
`.local/controller-fixture` directory under that exact workspace. All cooperating
launchers for that project/workspace must use this namespace, independent of cwd or
branch. Another checkout/host or a noncooperating writer is outside its protection.
No profile discovery, registry, daemon, DB, agent adapter or MCP service is added.

The kernel exclusive advisory lock remains on the same open lock inode until Close.
It is never removed/replaced or broken using PID, TTL or lease expiry. Private directory
mode is 0700; regular lock/journal files are 0600, nonblocking, no-follow and close-on-exec.
Namespace/lock identity changes fail closed. This is a cooperating local process
contract, not global Notion CAS/fencing or protection against a privileged writer.

One bounded canonical JSON ledger retains consumed task/run AND task/claim identities
across restarts, including confirmed results. A record carries a versioned provider-neutral
controller identity, provider_id represented by `Provider=codex`, S1 binding/nonce/fence/lease,
S2 source/brief/receipt pins, deadline, sequence, optional process/session observations,
bounded immutable payload/delivery digest and sync stage. Codex is the only supported
Phase 1 provider. Controller run and provider session stay separate; no generic router exists.

Each transition writes an exclusive same-directory temporary file, syncs it, renames
it atomically and syncs the directory. Failure poisons the open instance and leaves
failed evidence intact. Reopening with missing/corrupt/noncanonical/duplicate/alias JSON
or an unfinished temporary record blocks. Digest detects corruption; it is not authentication.
The bounded ledger stops at 1 MiB/128 records rather than deleting consumed history.
SIGKILL/process-restart fixtures test this protocol; power loss/device flush ordering
and filesystem/platform portability remain unqualified.

## Existing contracts and recovery

The caller must supply an approved profile/contract, current `GitSource.Check` proof,
S1 `ClaimState`, and successful S3 fixture preflight before `IntentFixture`.
Journal validates the matching existing bindings and S1 claim schema before INTENT
consumption and again on reopen, including exact bounded nonce text. It does not create a grant, read
credentials, verify an evidence issuer or replace the caller's source verification.
Tests reuse the unchanged S3 fixture and its explicit modeled S1/S2 proof. Existing
S2 actual local Git verification and S1 admission tests remain authoritative.

Durable INTENT consumes the run/claim before a caller's fake delivery. Both pre-spawn
and post-spawn crashes with only INTENT recover as UNKNOWN; neither PID absence nor
lock reacquisition permits another delivery. Any unresolved run blocks a different
run in the same namespace. The original 18-state design remains the reference;
stage A does not implement OS observation, killing, running-process attachment or
the live recovery states.

Result recording requires the same identity and a complete non-PID-only fixture
process/cleanup observation before the execution deadline. It accepts only unverified
completion, blocked or failed outcomes. Results and process/delivery identity cannot
be replaced. Recovery returns copied immutable result data; it grants no write or
launch. Reporting may outlive the execution deadline within the same valid claim lease.
Stale source/brief/receipt, owner/nonce/fence/lease or workspace blocks recovery.

Nil/mismatched readback records SYNC_UNKNOWN. Exact S1 result/key/payload readback
records SYNC_CONFIRMED. There is no Notion writer or automatic resend: a sole-writer
fixture may reconcile the same saved result, while ambiguous effects remain UNKNOWN.
S1 `conditional-replace` is a fixture value contract, not proof of Notion CAS support.

SIGKILL before intent/after intent/after consumer/after durable result, lost response

No existing S1/S2/S3, core, reader, executor/parser or CLI behavior changes. The CLI

and evidence. A fixture pass, delivery confirmation or exit0 cannot produce ACCEPTED/DONE.


## Stage B development connector

Stage B is a separately authorized development prerequisite exception under MTT-589.
Its correction budget is separate from Stage A's preserved exhausted 2/2. Live host,
launcher, workspace, credentials, Notion writes, native provider and Pilot approvals
remain pending. No CLI command or activation toggle is added.

`codex.NewFixtureBridge` connects the scoped `AccessReader`, actual `GitSource.Check`,
existing S1 binding/local claim transition, Stage A ledger and fake Executor. An explicit
development reference and matching scoped read reference are required; native Executor
mode is rejected as LIVE_AUTH_PENDING. Model native/sandbox/cleanup observations stay
fixtures. A copied finite environment reaches the fake runner and the native process
helper supports an explicit environment without changing legacy nil-env behavior.
No authentication/configuration file is discovered, copied or extracted.

`journal.OpenControllerFixture` requires an explicit canonical controller-owned root
outside the source workspace (neither may contain the other). The fixed namespace and
kernel inode lock stay the same; a ledger binds storage root, source workspace/project
and all previous consumed records. Original `OpenFixture` and version1 Stage A bytes
remain compatible. Actual runtime storage is not chosen by the implementation.

The connector keeps the lock through scoped reads, proof/brief/receipt checks, local
fence increment and durable INTENT, post-intent rechecks and final pre-spawn checks.
Raw Notion foreign owners, live leases or nonce conflicts fail closed before any local
overlay. Local metadata is not a Notion atomic claim; Reader/AccessReader.Claim remain
denied. INTENT/UNKNOWN and consumed identities never grant another provider attempt.

`notion.ResultDelivery` prepares one caller-authorized existing paragraph block with
fixed official HTTPS GET/PATCH, supplied token and transport, bounded body and no
redirect/default transport/append/creation/retry. Its wire operation is rich-text
replacement, never API CAS. The old ResultHandoff conditional-replace remains a local
binding/check contract. The exact canonical result envelope is bounded to one 2000-byte
text value; oversized or conflicting data blocks instead of truncation or bulk writes.
It pins the public writer reference, project/workspace/task/page/block and supported
wire operation in the durable INTENT identity before consumption. The same pin is
checked on reopen/current/recovery and included in the canonical result envelope.
Missing or changed pins never acquire a new writer target; historical Stage A bytes
remain compatible without automatic Stage B delivery adoption.
It verifies block/page/type and exact saved envelope on readback. Exact `in_trash`
must be boolean false. Deprecated `archived` may be absent; when supplied it must
also be boolean false. Null, aliases, duplicates, wrong types or deleted blocks
cannot permit a PATCH or delivery confirmation; unrelated extensions remain valid.

Durable RESULT_DURABLE precedes all delivery. SYNC_UNKNOWN is persisted before a PATCH,
so crash/response loss cannot cause a second blind write. Matching readback confirms
only projection delivery. Restart with an unattempted durable result may deliver that
same saved result once; uncertain writes permit only readback/manual reconciliation.
No result, process identity or expired/stale source proof is promoted to acceptance.

Focused TestB regressions use actual task-local Git objects and inert receipt projections,
scoped Reader with in-memory HTTP, the Go test binary as a fake consumer in an explicit
sealed environment, fixture cleanup and one supported result PATCH/readback. Native mode,
missing grants/access, owner/lease/source/brief/native/environment/nonce drift, failed
intent, conflicting cleanup/result and unknown response all remain denied or UNKNOWN.
Current native/Codex auth/sandbox/OS cleanup and real Notion schema/access/effects still
require separate operating qualification. Hosted CI and the actual Pilot are not run.

Focused recovery tests also cover changed writer references/blocks in RESULT_DURABLE
and SYNC_UNKNOWN, absent/unknown operation pins, contract mismatch, deleted or malformed
block readback, supported deprecated-field omission and extension compatibility.

## Default-off native activation candidate

This separately authorized feature reuses Stage A/B rather than adding a new stage,
service or CLI launch option. Their exhausted correction budgets remain 2/2 each;
the activation candidate has its own maximum two corrections. Source acceptance is
not operating approval, and MTT-589 remains BLOCKED until the operator qualifies the
actual targets. MTT-575 is not run; MTT-599 assignment/base/dependencies are unchanged.

`NewNativeBridge` requires an explicit enabled `NativeActivation`, separate approval
reference and trusted Grant issuer, exact execution/readback deadlines, and a host-owned
`Qualify` callback. Zero values deny before journal creation. The constructor installs
`nativeRunner` itself; a supplied fake executor cannot become a native execution path.
`NewFixtureBridge` still rejects native mode. The CLI remains dry-run only.

The trusted caller must independently verify the operator's authority and the callback's
provenance. Strings, model output, Notion status and fixture observations are not that
trust root. `NativeLaunch.Digest()` binds approval/issuer, contract, host Grant, source
proof/receipts, native identity, controller root, birth identity, sealed environment,
result target/operation and both deadlines. Each qualification echoes this binding,
its purpose (`open`, `spawn`, `result`), measured time and validity. Spawn additionally
requires **ChatGPT** login in that exact sealed environment, actual read-only sandbox,
network restriction and non-PID-only cleanup qualification. There is no API-key fallback,
credential discovery, login/OAuth flow or plugin-session transfer implementation.

Native path/hash/version (stable 0.161.0) are checked independently of S3 fixture paths;
the canonical native executable may be outside the source checkout. Exactly HOME,
CODEX_HOME and TMPDIR are passed with fixed PATH. They must be distinct, private 0700
current-user directories inside the explicit controller root, outside the journal's
`.local` namespace and source workspace. At spawn they must be empty, rejecting hidden
config/MCP/auth-file inheritance. This intentionally blocks file-cache auth reuse.
An operator must prove an officially supported auth mechanism under these constraints;
otherwise activation remains LIVE_AUTH_PENDING. This code neither attests an OS sandbox
nor makes a binary hash check an atomic executable-identity guarantee. Actual sandbox,
network, executable replacement protection and descendant cleanup must be measured by
the trusted host before it may issue a positive qualification. The existing runner's
fixed read-only argv, stdin brief, bounded output and process-group cleanup are reused.

Scoped Reader, actual Git source/brief/receipt rechecks, raw owner/lease rejection,
local singleton and durable intent-before-spawn remain on the shared Stage B path.
A new optional `ExecutionDigest` pins the native activation plan in the journal;
missing/changed pins cannot upgrade a fixture/old record into native authority.
Existing records omit this field and preserve their canonical bytes. UNKNOWN/consumed
runs cannot restart. Cleanup runs under an independent bounded five-second context even
if execution is cancelled; incomplete/ambiguous cleanup leaves INTENT/UNKNOWN.

Only an immutable durable result can reach the pinned ResultDelivery. Recovery requests
result qualification, not login or a fresh provider spawn, and can outlive the execution
deadline within the approved readback deadline and existing valid claim lease. An
uncertain PATCH is followed by exact readback only; an empty/unknown response after
uncertainty requires manual reconciliation. The approved readback deadline bounds the complete Native Run, qualifier and result
I/O contexts. Actual time/context is rechecked after qualification and response; late
observations cannot confirm delivery, even if a transport ignores cancellation.
Readback still confers no acceptance/DONE.

### Authentication and Notion delivery limits

The official [Codex authentication guide](https://developers.openai.com/codex/auth)
supports ChatGPT subscription login without a new API key. A login-status success in
the ordinary user environment does not establish access in sealed HOME/CODEX_HOME.
The development status probe found existing ChatGPT login, but the same stable native
reported not logged in under empty sealed directories. No auth files/tokens were read,
copied, linked or provisioned. Sealed native authentication remains **UNQUALIFIED**.

The official [Notion MCP tool list](https://developers.notion.com/guides/mcp/mcp-supported-tools)
and current connected tools expose page-oriented fetch/update, not the exact raw block
GET/PATCH interface used here. No Notion server was listed in the inspected CLI MCP
configuration. OAuth MCP authentication is not a REST bearer credential for this adapter.
The current OAuth route is **NOTION_DELIVERY_UNQUALIFIED**; page-wide Markdown editing
is not a substitute. No new integration/token/OAuth flow or MCP client is introduced.
The trusted host must separately qualify an authorized exact existing paragraph,
sole writer and supported transport before returning a positive result qualification.

and ambiguous delivery behavior. They do not prove live login, provider inference,

and actual runtime Notion writes during development remain zero.
