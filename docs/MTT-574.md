# MTT-574 stage A: local fixture journal

Stage A implements local fixture ownership and recovery only. The explicit user grant
partially exempts this stage from MTT-589's unresolved live approval. Depends On remains
unchanged. MTT-589 stays BLOCKED/HUMAN_DECISION with FIXTURE_POLICY_APPROVED /
LIVE_AUTH_PENDING. Stage A acceptance is not full MTT-574 acceptance or DONE.

## Fixed scope and persistence

`journal.OpenFixture` takes an explicit canonical project profile and uses the fixed
`.local/controller-fixture` directory under that exact workspace. All cooperating
launchers for that project/workspace must use this namespace, independent of cwd or
branch. Another checkout/host or a noncooperating writer is outside its protection.
No profile discovery, registry, daemon, DB, agent adapter or MCP service is added.

The kernel exclusive advisory lock remains on the same open lock inode until Close.
It is never removed/replaced or broken using PID, TTL or lease expiry. Private directory
mode is 0700; regular lock/journal files are 0600, nonblocking, no-follow and close-on-exec.
Namespace/lock identity changes fail closed. This is a cooperating local process
contract, not global Notion CAS/fencing or protection against a privileged writer.

One bounded canonical JSON ledger retains consumed task/run AND task/claim identities
across restarts, including confirmed results. A record carries a versioned provider-neutral
controller identity, provider_id represented by `Provider=codex`, S1 binding/nonce/fence/lease,
S2 source/brief/receipt pins, deadline, sequence, optional process/session observations,
bounded immutable payload/delivery digest and sync stage. Codex is the only supported
Phase 1 provider. Controller run and provider session stay separate; no generic router exists.

Each transition writes an exclusive same-directory temporary file, syncs it, renames
it atomically and syncs the directory. Failure poisons the open instance and leaves
failed evidence intact. Reopening with missing/corrupt/noncanonical/duplicate/alias JSON
or an unfinished temporary record blocks. Digest detects corruption; it is not authentication.
The bounded ledger stops at 1 MiB/128 records rather than deleting consumed history.
SIGKILL/process-restart fixtures test this protocol; power loss/device flush ordering
and filesystem/platform portability remain unqualified.

## Existing contracts and recovery

The caller must supply an approved profile/contract, current `GitSource.Check` proof,
S1 `ClaimState`, and successful S3 fixture preflight before `IntentFixture`.
Journal validates the matching existing bindings and S1 claim schema before INTENT
consumption and again on reopen, including exact bounded nonce text. It does not create a grant, read
credentials, verify an evidence issuer or replace the caller's source verification.
Tests reuse the unchanged S3 fixture and its explicit modeled S1/S2 proof. Existing
S2 actual local Git verification and S1 admission tests remain authoritative.

Durable INTENT consumes the run/claim before a caller's fake delivery. Both pre-spawn
and post-spawn crashes with only INTENT recover as UNKNOWN; neither PID absence nor
lock reacquisition permits another delivery. Any unresolved run blocks a different
run in the same namespace. The original 18-state design remains the reference;
stage A does not implement OS observation, killing, running-process attachment or
the live recovery states.

Result recording requires the same identity and a complete non-PID-only fixture
process/cleanup observation before the execution deadline. It accepts only unverified
completion, blocked or failed outcomes. Results and process/delivery identity cannot
be replaced. Recovery returns copied immutable result data; it grants no write or
launch. Reporting may outlive the execution deadline within the same valid claim lease.
Stale source/brief/receipt, owner/nonce/fence/lease or workspace blocks recovery.

Nil/mismatched readback records SYNC_UNKNOWN. Exact S1 result/key/payload readback
records SYNC_CONFIRMED. There is no Notion writer or automatic resend: a sole-writer
fixture may reconcile the same saved result, while ambiguous effects remain UNKNOWN.
S1 `conditional-replace` is a fixture value contract, not proof of Notion CAS support.

## Validation and live boundary

Focused regressions cover competing controller lock/intent, a real fake consumer,
SIGKILL before intent/after intent/after consumer/after durable result, lost response
and exact same-result readback, stale identities and damaged storage. Run:

```text
go test ./internal/adapter/codex -run '^Test574' -count=1 -v -timeout=60s
go test ./internal/adapter/codex -race -run '^Test574' -count=1 -v -timeout=60s
make check
```

No existing S1/S2/S3, core, reader, executor/parser or CLI behavior changes. The CLI
remains dry-run. Actual Notion authentication/claim/result writes, provider jobs,
sandbox/environment/process cleanup and the MTT-575 E2E pilot require separate grants
and evidence. A fixture pass, delivery confirmation or exit0 cannot produce ACCEPTED/DONE.
