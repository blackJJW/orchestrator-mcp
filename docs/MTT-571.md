# Bootstrap contract

This public baseline contains the independently accepted native Go bootstrap. Public documentation omits private coordination pages, personal paths and raw evidence. The accepted runtime source, tests, fixtures, module and build recipe are unchanged.

## Implemented behavior

- Explicit profile input, exact task and permission allowlists, default denial and project isolation.
- Strict profile JSON and bounded regular-file reads, including descriptor validation and nonblocking FIFO rejection.
- Pure synchronous scope decisions and versioned CLI JSON, with distinct input and usage errors.
- Inert local fixtures for two workspaces. Every CLI decision remains a dry run.

The canonical validation is `make check`: formatting, unit tests, vet and native build. The accepted validation covers malformed profiles, case aliases and duplicate keys, missing authority, symlink escapes, workspace mismatch, FIFO rejection and replacement races. Existing native CLI evidence covers allowed and denied dry-run decisions and rejects execution options. Private validation artifacts remain outside Git.

## Publication contract

The initial commit allowlist is `.gitignore`, `AGENTS.md`, `Makefile`, `README.md`, this contract, `go.mod`, the CLI, profile and core source/tests, and the two inert profiles/workspaces. It excludes adapter candidates and all local evidence, logs, binaries, caches, credentials and personal configuration.

Inspect the exact staged paths, modes and bytes before committing. Inspect commit metadata and the complete prospective history before pushing. Use a repository-local GitHub noreply author identity. Publish with a normal push; stop on unexpected remote history or sensitive material. Verify the remote commit and tree after publication. A source-set SHA-256 is an evidence identity and is not a Git commit SHA.

Preserve private source candidates and historical validation records outside the published baseline. Do not overwrite an existing working directory to make it match `main`. Later candidates belong on separate review branches only when their scope can be isolated safely.

## Unverified scope

Provider authentication and execution, live admission or atomic claims, external source verification, MCP/Docker service implementation and runtime qualification are outside this baseline. Publication does not satisfy these conditions. Other operating systems and toolchain versions have not been qualified by the accepted local evidence.
